# 台湾实时监控使用说明（非技术人员版）

## 日常打开

1. 双击项目根目录的 `启动台湾Demo.bat`。
2. 浏览器打开后，点击顶部“来源健康”。这里看来源总数、ACTIVE、待核验、最近成功、失败原因和连续失败次数。
3. 点击“最近两小时”，查看已列来源最近发现的内容。`OPINION` 代表 X／YouTube／KOL 内容，不是已核实财经事实。
4. 点击每条内容的 `Raw` 查看系统保存的原始 Evidence；点击“原帖”打开原始 URL。

本地地址：`http://127.0.0.1:8765/radar`

## 第一次启用计划任务

在项目目录打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install_realtime_radar_task.ps1
```

系统建立当前 Windows 用户下的任务 `Global X Finance - Taiwan Realtime Radar`。调度器每 10 分钟启动；X 来源每 10 分钟到期，YouTube 每 30 分钟到期。任务重启后从 SQLite 的 `next_due_at` 继续，不会清空上次成功结果。

手动执行一次（用于排查，不需要日常执行）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_realtime_radar.ps1
```

查看任务状态：

```powershell
Get-ScheduledTask -TaskName "Global X Finance - Taiwan Realtime Radar"
Get-ScheduledTaskInfo -TaskName "Global X Finance - Taiwan Realtime Radar"
```

## 页面怎么看

- `VERIFIED_ACTIVE`：身份入口已核验，且本雷达已配置采集。它不代表覆盖全平台。
- `VERIFIED_MANUAL_ONLY`：入口已核验，但当前只允许人工／按需处理。
- `NEEDS_VERIFICATION`：候选或入口还缺身份、技术或条款核验。
- `BLOCKED`：存在 robots、付费墙、许可或其他明确阻塞，不会绕过。
- `连续失败次数`：连续运行失败的真实计数；成功后归零。
- `最近成功时间`：失败不会覆盖这个值。
- `INITIAL_BACKFILL`：第一次建立基线时保存的最近可见旧内容，不用于实时延迟平均值。

## 常见情况

- “最近两小时”为空：代表已列来源在此范围没有新发现，系统不会补假数据。
- 某个来源失败：在“来源健康”查看真实错误；其他来源与上一次成功结果仍保留。
- X 内容延迟较高：第三方只读适配器不提供官方 SLA，应根据连续运行记录调整频率或换成获得授权的官方方式。
- 电脑关机：Windows 无法采集；下次开机任务会继续运行，但关机期间不是 24/7 监控。

## 边界

系统不会自动点赞、关注、回复或发帖，不会使用浏览器脚本规避平台限制，不会把观点写成财经事实，也不构成投资建议。
