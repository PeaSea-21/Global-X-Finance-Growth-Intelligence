## 2. 可以直接复用的能力

### Global X Finance：可信事实底座

- 同一核心引擎加载台湾、美国 Market Pack，不复制项目。
- 17 个台湾来源入口的注册、状态校验与 `publisher_group` 去重。
- 原始 Evidence 追加保存，保留 URL、发布时间、抓取时间、内容哈希和原始响应；下游不能覆盖 Raw Evidence。
- URL / `content_hash` 精确去重，`UNKNOWN`、`NEEDS_VERIFICATION`、`SOURCE_CONFLICT` 可保存。
- TWSE OpenAPI 三个官方日频数据集的真实采集、标准化、实体映射与回查。
- 当前演示库有 1,681 条 Raw Evidence、1,681 条标准化记录、1,681 条实体关联和 66 张官方规则卡。
- 本地网页、筛选、分页、数据新鲜度、Evidence 回链和 Windows 一键启动。

### xHotTopic：X 关注池发现引擎

- 从关注账号 CSV 筛选近 30 天活跃账号，并采集滚动 24 小时公开内容。
- 保存原始响应、页级哈希、游标、抓取时间、manifest 和覆盖状态，可离线重放。
- 确定性话题归并、跨账号共振、时间衰减、互动评分和 V1/V2 影子评测。
- LLM 只做相关性筛选和文字归纳，不参与热度真值计算。
- 模型精确缓存、用量账本、失败不覆盖上次成功快照、单实例锁和本地看板。
- 已有 72 项测试，当前实跑全部通过；源码也通过 `compileall`。
- 明确不等同于 X 全站趋势，不自动关注、不自动发帖、不提供投资建议。

### 已有真实输出证明了什么

2026-08-03 的最后完整 xHotTopic 输出实际处理 1,278 个可观察账号，得到 1,739 条 24 小时内容、36 个合格候选和 Top 10；该次错误数为 0，但覆盖状态是 `partial`，完整率为 0、部分覆盖率为 100%。这证明流程跑通过，不证明当前仍在持续监控，也不证明覆盖整个 X。

## 5. 当前 X 监控延迟与成功率

### 当前端到端状态

**NOT_RUNNING / NOT_REALTIME。** 本机没有 `X-HotTopic Live Refresh` 计划任务，`output/xiaopi_live` 与 `data/xiaopi_live` 没有 live 状态；最后完整输出生成于 2026-08-03T04:47:06Z。到本次审计时已超过 11 天。因此不能对业务方说“现在每 30 分钟都有热点”。代码支持半小时调度，不等于本机已经持续运行。

### 2026-08-14 小样本连通性测试

- 样本：关注池内 5 个财经相关公开账号，每个请求一页；不调用 LLM、不写项目数据库。
- 传输成功：5/5，样本成功率 100%。
- 请求耗时：平均 1.486 秒，中位数 1.552 秒，范围 1.150–1.888 秒。
- 返回内容中最新帖龄：7.4 分钟至 1,718.4 分钟；这是“账号最近是否发帖”，**不是系统发现延迟**。
- 适配器是 FxTwitter 第三方接口，不是 X 官方 API；一次 5 账号成功不能外推为 1,278 个账号的持续成功率，也不能证明长期授权、稳定性或服务等级。

逐样本结果见 `deliverables/X监控实测_P01.csv`。在部署真实定时任务并连续保存至少 7 天运行记录前，端到端成功率与 P50/P95 发现延迟应标记 `UNKNOWN`。

## 6. 五种原创账号 Style Pack v0.1

由于五个账号素材为 `NOT_PROVIDED`，以下是不同定位的原创原型，不模仿具体大 V，不逐句改写原帖。

| Style Pack | 定位 | 典型内容 | 文字特点 | 必须避免 |
|---|---|---|---|---|
| `TW_MARKET_DESK` | 台湾官方盘面台 | TWSE、公司公告、监管数据 | 事实优先、短句、数字带日期与 Evidence | 把日频数据写成实时、荐股、猜数字 |
| `GLOBAL_MACRO_BRIDGE` | 全球宏观到台湾的连接器 | 利率、汇率、政策、海外市场对台影响 | 先说事件，再列可能传导路径；不把推演写成事实 | 把相关性写成因果、保证走势 |
| `TECH_SUPPLY_CHAIN` | 科技与半导体产业解释 | AI 硬件、晶圆、封测、供应链公告 | 名词解释、上下游关系、公司原文优先 | 用 KOL 说法替代公司或交易所事实 |
| `RISK_FACTCHECK` | 市场传言核验台 | 热门说法、冲突消息、截图数字 | 分成“已证实 / 未证实 / 相互冲突”，语气克制 | 为了快而补全 UNKNOWN、断言真假 |
| `COMMUNITY_PULSE` | 社区观点雷达 | X、YouTube、论坛争议与共识 | 明确标 `OPINION`，呈现支持与反对两侧 | 冒充作者、复制原句、把声量当事实 |

每个 Style Pack 都应版本化，至少包含：受众、选题范围、语气、段落结构、长度、可用证据类型、禁用表达、风险提示、原创性阈值和人工审核要求。收到真实五账号数据后才能做 v0.2 校准。

## 7. 统一内容草稿数据结构

```text
ContentDraft
  draft_id / topic_id / market
  style_pack_id / style_pack_version
  title / body / language
  claim_ids[] / evidence_links[]
  fact_blocks[] / opinion_blocks[] / unknown_blocks[]
  source_publisher_groups[] / independent_source_count
  data_freshness / as_of_time
  originality_check / similarity_references[]
  risk_flags[] / investment_advice_flag=false
  status=DRAFT|EDITOR_REVIEW|APPROVED|REJECTED|PUBLISHED_MANUALLY
  generated_by / assigned_to / reviewed_by
  created_at / updated_at / approved_at
```

硬规则：没有 Evidence 的财经事实不得进入 `APPROVED`；KOL、YouTube 和论坛内容进入 `opinion_blocks`；同一 `publisher_group` 只计一个独立来源；`UNKNOWN` 不自动补齐；`PUBLISHED_MANUALLY` 只记录员工手工发布结果，不提供自动发帖动作。

## 8. 发布后反馈结构

```text
PerformanceSnapshot
  snapshot_id / draft_id / account_id
  platform_post_id / platform_post_url
  published_at / observed_at
  observation_window=1H|6H|24H
  views / likes / replies / reposts / quotes / bookmarks
  follower_count_at_observation
  views_delta / views_per_hour / engagement_rate
  adopted=true|false / editor_id
  metric_evidence_url / metric_capture_method
  formula_version / missing_fields[]
```

浏览量、增长速度和采用率是运营反馈，不是财经事实。平台未返回的字段保存 `UNKNOWN`，不能写成 0。1H、6H、24H 必须分别保存快照，不能覆盖前一版。

## 9. 十几位内容员工的日常流程

1. **来源值班**：系统把官方、媒体和 X 候选分栏；未授权来源不自动采集。
2. **证据分诊**：员工判断 `FACT / OPINION / UNKNOWN / SOURCE_CONFLICT`，绑定 Raw Evidence。
3. **选题队列**：xHotTopic 贡献“正在共振的候选”，Global X Finance 贡献“可以核验的事实”。
4. **认领与防撞**：员工认领选题，显示负责人、截止时间和账号，避免十几人重复写。
5. **Style Pack 起草**：AI 按账号定位出原创草稿，编辑可改写；不得模仿具体作者。
6. **双层审核**：事实 / Evidence 审核与文案 / 风险审核分开；冲突未解则不发布或明确标注。
7. **人工发布**：员工复制或手工发布到 X；系统不持有自动发布能力。
8. **反馈回填**：记录是否采用和 1H / 6H / 24H 浏览量，日复盘选题，周复盘 Style Pack。

建议班次看板只显示五个状态：`待核验 → 可写 → 起草中 → 待审核 → 已手工发布`。每条选题必须显示 Evidence 数、独立 publisher_group 数、数据时间和最后抓取时间。

## 10. 推荐整合方案

先做“适配器整合”，不要立即把两个仓库硬合并：

```text
TWSE / 官方 / 未来已授权媒体 ─→ Global X Finance Evidence
X 关注池 ─→ xHotTopic 候选、热度、覆盖状态
两者统一为 TopicCandidate + EvidenceBundle
            ─→ 员工选题队列
            ─→ Style Pack 原创草稿
            ─→ 人工审核与手工发布
            ─→ 1H / 6H / 24H 反馈
```

职责边界：Global X Finance 决定“证据是否可追溯、来源是否允许、事实是否已核验”；xHotTopic 决定“关注池里什么正在共振”；工作台决定“谁来写、按哪个账号风格写、是否采用以及表现如何”。热度不能代替事实核验，观点声量不能代替独立信源。

## 12. 最大风险与当前缺口

1. **持续监控尚未运行**：当前不是半小时实时报榜，最后产物已过期。
2. **台湾来源覆盖不完整**：已验证台湾 X、YouTube、论坛来源均为 0；媒体采集授权也未完成。
3. **第三方 X 依赖**：FxTwitter 与本地配置的模型 / 搜索中转不是 X 官方事实源，稳定性、条款、隐私和长期可用性需要单独评估。
4. **观点污染事实**：X、KOL、YouTube 与论坛默认是 `OPINION`；不经官方或公司 Evidence 交叉验证不能升级为事实。
5. **风格尚未校准**：缺少五账号历史内容与数据，当前 Style Pack 只是原创方向草案。
6. **绩效基线缺失**：没有采用率和 1H / 6H / 24H 历史快照，无法承诺增长效果。
7. **多人协作冲突**：没有认领、锁定、审核责任和回退机制时，十几人会重复劳动或抢发同题。

## 13. 需要业务方提供的资料

- 希望纳入台湾监控的 X 账号、YouTube 频道、论坛清单及其使用 / 采集授权判断。
- 内容部人数、班次、每日产量、审核链、响应时限和重复选题处理规则。
- 成功指标的基线与目标：采用率、从发现到可写的时长、事实退回率、1H / 6H / 24H 浏览量增长。

## 14. 审计结论

项目已有两块重要资产：一块解决“事实是否有证据”，一块解决“关注池里什么正在升温”。当前缺的不是第三套抓取器，而是可信来源扩充、持续运行、统一选题队列、五账号真实 Style Pack、多人审核和反馈闭环。建议暂停广告方向，把下一阶段资源集中在这层整合上。
